# KOLO Together

Мобильное пространство для двух равноправных партнёров: маленькие дела, общие цели и забота без соревнования.

## Разработка

Node.js 24 LTS (`.nvmrc`), npm. В текущей облачной среде при необходимости используйте `npm --cache /tmp/kolo-npm …` (домашний каталог недоступен для записи).

```sh
npm ci
npm run dev -- --host 0.0.0.0
```

Приложение запускается без `.env`. Пять разделов: Сегодня, Дела, Цели, Награды, Мы. Демо-дела можно добавить и отметить; данные живут только в памяти до перезагрузки страницы. Цели и награды в демо — явно обозначенные примеры без серверных операций. В деморежиме XP, Coins и Together XP не начисляются. В демо кошелёк, переводы, покупки и подписки недоступны; демо не изображает финансовые операции.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run preview -- --host 0.0.0.0
```

Для `npm test` нужен Docker: UI-тесты работают без переменных Supabase, а проверки RLS/RPC запускаются в отдельном disposable PostgreSQL 17. `npm run test:unit` и `npm run test:db` запускают наборы отдельно. Сборка находится в `dist/`. `netlify.toml` задаёт сборку и SPA fallback для прямых переходов, например `/goals`. Деплой из этой задачи не выполняется.

## Архитектура

- `src/App.tsx`: маршруты, адаптивная оболочка, демонстрационный workflow.
- `src/features/`: типы и локальный источник демоданных; TanStack Query управляет состоянием запросов.
- `src/components/ui/`: локальные редактируемые компоненты по архитектуре shadcn/ui (Radix Slot, CVA, Tailwind); настройки генератора — `components.json`, импорт `@/`.
- `src/components/states.tsx`: загрузка, отсутствие данных, ошибка с повтором.
- `src/lib/`: утилиты и опциональный Supabase-клиент.
- `src/integrations/`: контракты платформы и биллинга.
- `src/features/rituals/`: добровольные совместные ритуалы, согласования и UTC-история без очков; правила — `docs/couple-rituals.md`.
- `src/features/statistics/`: достижения, личная статистика, UTC-серии и серверный feed в «Мы»; правила — `docs/achievements-statistics.md`.
- `src/features/goals/`: совместные цели, согласованные шаги, история, безопасный общий бонус; правила — `docs/couple-goals.md`.
- `src/features/rewards/`: добровольный магазин, согласия, покупки и история Coins; правила — `docs/rewards-store.md`.
- `src/features/tasks/`: форма, фильтры, согласия, повторения, собственное выполнение и игровой прогресс.
- `docs/tasks-economy.md`: правила начислений, UTC-периоды, схема/RPC и двухаккаунтный checklist.
- `src/features/auth/`, `profile/`, `couple/`: Auth, профили и безопасное пространство пары.
- `supabase/migrations/`: схема, RLS и атомарные RPC; `supabase/tests/` — тесты на PostgreSQL.
- `docs/supabase.md`: Dashboard, применение миграций, обновление типов и тестирование.
- `docs/product-spec.md`: продуктовые правила.

Тема использует CSS-переменные, системное предпочтение и локальный выбор. Интерфейс учитывает safe area, клавиатурный фокус и reduced motion. Tailwind CSS 4 подключён через Vite.

## Supabase

Скопируйте `.env.example` в `.env.local` и при необходимости задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Это публичная конфигурация браузера. **Не используйте service_role, access tokens и другие секреты в VITE-переменных.** При отсутствии или некорректном URL клиент равен `null`; старт приложения не падает. При наличии конфигурации включаются реальные Auth-экраны, защищённые маршруты, редактирование профиля, создание пространства и одноразовые приглашения по email. Прежде примените миграцию к отдельно разрешённому тестовому проекту и настройте Dashboard по [инструкции](docs/supabase.md). С новой миграцией работают задания, согласия и серверные XP/Coins/Together XP. Миграция этапа 4 добавляет магазин добровольных наград за собственные Coins с возвратом; миграция этапа 5 добавляет совместные цели с согласиями и однократным +50 Together XP; этап 6 добавляет достижения без новых начислений, статистику и приватную историю с серверной пагинацией в «Мы»; этап 7 добавляет отдельные добровольные ритуалы в «Сегодня»/«Мы» без начислений; демооперации к реальному аккаунту не привязываются. Миграции к удалённой базе не применялись.

## Capacitor и RevenueCat

SDK намеренно не установлены. После выбора iOS/Android реализуйте `PlatformAdapter`, добавьте платформенные проекты и их lifecycle/safe-area настройки в отдельной задаче. Для RevenueCat реализуйте `BillingAdapter` только после определения платформ, продуктов и entitlements. Покупки и restore требуют нативных тестов, а выдача доступа — серверной проверки/webhooks. Coins не являются денежным балансом и не связаны с подписками. Текущий `billing = null` означает отсутствие платёжной возможности.

Для дополнительной мобильной проверки demo UI в системном Chromium: запустите production preview и `npm run test:ritual-browser`. Проверяются две ширины и обе темы, без облачных аккаунтов. Подробности — [docs/couple-rituals.md](docs/couple-rituals.md).

## Емоційна близькість (етап 8)

У «Сегодня» — необов’язковий український check-in, у «Мы» — «Пізнаємо одне одного»: власний настрій, вісім авторських опитувань і спільна гра «Між нами» на 150 запитань. П’ять основних вкладок збережено. Без XP/Coins, діагностики чи зовнішнього AI. Чернетки приватні, розкриття потребує явної згоди й завершення обома. Без Supabase — лише read-only оформлення.

Документація: [настрій](docs/emotional-checkin.md), [опитування](docs/couple-questionnaires.md), [гра, RPC, приватність і розгортання](docs/between-us-card-game.md). Нова pending-міграція: `supabase/migrations/20261022120000_emotional_connection.sql`; автоматично remote не застосовується. `npm run check:connection-catalog` перевіряє JSON/SQL seed; опційні локальні Chromium checks: `npm run test:connection-browser` і `npm run test:connection-accounts -- /tmp/OWN-local-status.json http://127.0.0.1:4174` (інструкції в документації гри).
