# KOLO Together

Мобильное пространство для двух равноправных партнёров: маленькие дела, общие цели и забота без соревнования.

## Разработка

Node.js 24 LTS (`.nvmrc`), npm. В текущей облачной среде при необходимости используйте `npm --cache /tmp/kolo-npm …` (домашний каталог недоступен для записи).

```sh
npm ci
npm run dev -- --host 0.0.0.0
```

Приложение запускается без `.env`. Пять разделов: Сегодня, Дела, Цели, Награды, Мы. Демо-дела можно добавить и отметить; данные живут только в памяти до перезагрузки страницы. Цели, награды и профили — подготовленные состояния, не удалённые сервисы. XP, Coins и Together XP пока не начисляются. Кошелёк, переводы, покупки и подписки недоступны; демо не изображает финансовые операции.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run preview -- --host 0.0.0.0
```

Тесты рассчитаны на отсутствие переменных Supabase. Сборка находится в `dist/`. `netlify.toml` задаёт сборку и SPA fallback для прямых переходов, например `/goals`. Деплой из этой задачи не выполняется.

## Архитектура

- `src/App.tsx`: маршруты, адаптивная оболочка, демонстрационный workflow.
- `src/features/`: типы и локальный источник демоданных; TanStack Query управляет состоянием запросов.
- `src/components/ui/`: локальные редактируемые компоненты по архитектуре shadcn/ui (Radix Slot, CVA, Tailwind); настройки генератора — `components.json`, импорт `@/`.
- `src/components/states.tsx`: загрузка, отсутствие данных, ошибка с повтором.
- `src/lib/`: утилиты и опциональный Supabase-клиент.
- `src/integrations/`: контракты платформы и биллинга.
- `supabase/migrations/`: зарезервирован для будущих SQL-миграций.
- `docs/product-spec.md`: продуктовые правила.

Тема использует CSS-переменные, системное предпочтение и локальный выбор. Интерфейс учитывает safe area, клавиатурный фокус и reduced motion. Tailwind CSS 4 подключён через Vite.

## Supabase

Скопируйте `.env.example` в `.env.local` и при необходимости задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Это публичная конфигурация браузера. **Не используйте service_role, access tokens и другие секреты в VITE-переменных.** При отсутствии или некорректном URL клиент равен `null`; старт приложения не падает. Наличие конфигурации не включает реальные операции: auth, репозитории данных и RLS ещё предстоит реализовать. До подключения реальных данных нужны схема, RLS и тесты изоляции двух партнёров. Миграции к удалённой базе не применялись.

## Capacitor и RevenueCat

SDK намеренно не установлены. После выбора iOS/Android реализуйте `PlatformAdapter`, добавьте платформенные проекты и их lifecycle/safe-area настройки в отдельной задаче. Для RevenueCat реализуйте `BillingAdapter` только после определения платформ, продуктов и entitlements. Покупки и restore требуют нативных тестов, а выдача доступа — серверной проверки/webhooks. Coins не являются денежным балансом и не связаны с подписками. Текущий `billing = null` означает отсутствие платёжной возможности.
