# Щоденний емоційний check-in

«Як ти сьогодні?» у «Сегодня» та власний календар у «Ми → Пізнаємо одне одного → Наш настрій». Модуль українською. Участь необов’язкова, без винагород, серій, нагадувань із докором та діагнозів.

Один запис власника за календарний день UTC: вісім станів, інтенсивність 1–5, коментар до 500 символів, запит підтримки, добровільне поширення. Типово запис приватний. Власник редагує поточний день; минулі записи лише читаються. Сервер звіряє UTC-день **після** user → space locks; запит із учорашнім днем не створює сьогоднішній запис. Version CAS захищає зміни з двох вкладок, UUID повторює тільки вихідний запит.

Партнер бачить лише опублікований сьогоднішній запис, який адресований саме його нинішньому membership ID. Власна 30-денна історія, категоріальний календар та смужки інтенсивності не включають чужі приватні факти. Немає загального показника «здоров’я стосунків». Пропущений день — просто відсутність запису.

П’ять підтримувальних реакцій — не оцінки. Одна реакція партнера на запис, із можливістю заміни. Редагування настрою прибирає старі реакції, щоб вони не приписувалися новому змісту. Зняття поширення негайно закриває серверне читання реакцій і запису для партнера.

При виході будь-кого поширення відповідних записів вимикається. Повернення тієї ж людини не відновлює його автоматично. Власна історія лишається власнику. Новому партнеру не передаються ні попередні записи, ні їхні кількості чи агрегати.

Таблиці `connection_moods`, `connection_reactions`: RLS + authenticated SELECT, прямі записи заборонені. Записи через `connection_action` (`mood`, `react`), читання через `connection_read('home')`. Дозволені поля й довжини перевіряє PostgreSQL. Клієнт не передає user_id та не визначає серверний день.

Деморежим не зберігає check-in та не імітує серверних фактів. Не надсилаємо зміст зовнішнім AI/API. Уже законно прочитаний текст чи скриншот неможливо відкликати з пам’яті іншого пристрою.

Додаткове review: прямі RLS й `home` RPC перевірено після leave, повернення того ж партнера, створення двох нових пар та публікації нових mood у кожній. Колишній партнер не отримує ні новий запис, ні старий private запис. Автор бачить власний архів; свіжий партнер — лише явно відкритий йому поточний запис. Зв’язок shared mood додатково перевіряє власника обох membership references і спільний space, а не лише існування ID.
