# Опитування для самопізнання та діалогу

Вісім авторських тематичних опитувань по десять оригінальних українських запитань: турбота («Мова любові»), спілкування, кордони, конфлікти, майбутнє, побут, підтримка, романтика. Це **не клінічні методики**, не діагностика сумісності; наукову валідність не заявлено. Тексти не відтворюють сторонній психометричний інструмент.

## Дані й згода

Версія 1 каталогу з постійними ID: `src/features/connection/catalog.json`, тотожний seed у `20261022120000_emotional_connection.sql`. Каталог можна читати через RLS, але не змінювати клієнтом. Опубліковану версію надалі не перезаписувати: нова редакція отримує новий ID і міграцію.

Один партнер запрошує, другий явно приймає або відхиляє. До прийняття проходження недоступне; `resume` не обходить запрошення. На тему дозволена одна незавершена сесія простору. Кожен зберігає лише власні відповіді й може повернутися пізніше. UUID + незмінний payload/hash і початковий лічильник створень запобігають повторам невідомого результату, зокрема з двох вкладок.

Публікація відокремлена від збереження: власник заповнює всі десять відповідей та **окремо позначає згоду** на спільний звіт. Сервер перевіряє всі ID, типи/дозволені значення та `publish=true`. Ніхто не завершує за іншого. Чужі чернетки не доступні навіть через прямий SELECT; до завершення й згоди обох RPC повертає лише статус участі, а не відповідь. Незавершені чернетки не включаються в агрегати.

Можна відмовитися до розкриття: закрити участь; власні відповіді цієї сесії видаляються. Кнопка «Відкликати розкриття та видалити мої відповіді» працює також після звіту: видаляє лише власні відповіді, закриває сесію, прибирає спільний доступ. Чужий власний текст не видаляється. Після виходу зі простору власні рядки лишаються доступними лише автору через RLS; `connection_action('delete_own_history', id, …)` дозволяє видалити їх без чинного партнерства. UI керування доступний до виходу; окремий екран експорту/видалення архіву після виходу не входить у цей етап.

Спільний доступ прив’язаний до **двох точних membership ID**. Вихід закриває незавершені сесії та відбирає доступ до спільного змісту всіх попередніх сесій. Навіть колишній партнер після повторного вступу не отримує його автоматично. Завершені записи зберігаються приватно для автора до власного видалення або видалення акаунта. Уже прочитані копії дистанційно не стираються.

## Пояснюваний аналіз

`compareAnswers` — чиста детермінована функція. Для порядкової шкали 1–5 використовується відстань `abs(a-b)` (0–4); внутрішня близькість `1-distance/4`. Близькими названі відстані 0–1, істотними відмінностями — 3–4. Для довільного вибору/пріоритету порівнюється **meaning** варіанта, а не його індекс. Однаковий зміст = збіг, різний = тема для розмови. Перестановка варіантів не змінює результат.

Звіт описує конкретні пункти тематичного опитування, показує обидві відповіді, нейтральне пояснення, три запитання для розмови та три добровільні практичні кроки. Загального відсотка якості/сумісності немає. Це прості правила відображення поточних уподобань, а не статистична чи психологічна оцінка людини. Рекомендації локальні, заздалегідь написані; зовнішніх AI API немає.

## RPC

`connection_action`: `start_questionnaire`, `accept`, `decline`, `save`, `submit`, `pause`, `resume`, `close`, `erase_answers`, `delete_own_history`. `connection_read`: `home`, `sessions`, `session`, `request`. Читання не створює сесій і не відновлює мутацій. Лістинг — server-side keyset по `(created_at,id)`, по 20 рядків; cursor прив’язаний до actor/membership context/view. Це live-пагінація з часовою межею, **не** строгий MVCC snapshot. Пізні COMMIT вище курсора видно після оновлення першої сторінки.
