# Правила разработки KOLO Together

- Используйте текущий checkout; cloud-задача уже изолирована. Не создавайте worktree без запроса пользователя.
- Node 24, npm и `package-lock.json`; для повторной установки `npm ci`. Сохраняйте совместимость зависимостей, не обходите peer conflicts через force.
- Перед PR: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`. Проверяйте маршруты и мобильную навигацию.
- Интерфейс на русском, mobile-first, семантический HTML, видимый фокус, доступные имена и reduced motion. Цвета через CSS-переменные; поддерживайте обе темы.
- Соблюдайте `docs/product-spec.md`: равноправие, согласие, отсутствие наказаний и денежных имитаций.
- Разделяйте демоданные и реальные операции. Не включайте платежи, кошельки или выдачу entitlements как фиктивно успешные действия.
- Только публичные ключи в VITE-переменных. Не коммитьте .env, service_role, токены и пользовательские данные. Supabase необязателен для локального запуска.
- Не применяйте удалённые миграции, не меняйте production и не деплойте без отдельного разрешения. До реальных данных реализуйте RLS и проверки доступа.
- Capacitor/RevenueCat подключайте отдельной задачей после определения платформ. Не добавляйте нативные SDK заранее.
- Расширяйте локальные компоненты `src/components/ui`, поддерживая shadcn-совместимые алиасы. Формы — RHF + Zod, серверное состояние — TanStack Query.

- Auth/пары: следуйте `docs/supabase.md`. Не переносите привилегированные изменения членства из RPC в клиент. Сохраняйте порядок блокировок user → space, два места и одно активное пространство.
- При изменениях миграций запускайте `npm run test:db` на disposable PostgreSQL (Docker); моки UI не заменяют RLS/RPC тесты. `npm test` включает оба набора. Bootstrap тестовой Auth-схемы никогда не применяется к Supabase.
- Не логируйте session/invite tokens и не добавляйте их в query keys. Invite token передаётся во fragment и хранится только временно в sessionStorage. Не расширяйте доступ к чужим профилям за пределы активной пары.

- Задания и экономика: `docs/tasks-economy.md`. Награды только на сервере, не передавайте суммы/user_id/время в complete RPC. Сохраняйте unique keys, порядок блокировок и снимки наград.
- Любое изменение начислений/повторений/выхода проверяйте DB-тестами с конкурентными запросами; UI-моки не заменяют их. Никогда не проверяйте разрыв рабочей облачной пары или удалённые данные без отдельного согласия.
- Деморежим не создаёт серверные начисления и сессии. Списания/возвраты игровых Coins этапа 4 — только по `docs/rewards-store.md`; денежные переводы/кошельки не входят в этап.

- Магазин: сохраняйте reward_ledger положительным, coin_transactions — единственным зеркалом earn/spend/refund. Не удваивайте historical backfill. Порядок блокировок user → space → offer → purchase → progress; возврат не берёт чужой advisory lock. Проверяйте согласия, snapshots, request keys, single-use, rollback и leave refunds на PostgreSQL.

- Покупки: сохраняйте UUID и исходный p_expected_purchases одним intent; retry не должен брать свежий counter. Ошибка reward_purchase_changed требует нового явного подтверждения. Backfill проверять полным SQL-файлом на отдельной новой disposable БД, включая missing progress и откат DDL; старые удалённые данные не восстанавливать автоматически.

- Цели: следуйте `docs/couple-goals.md`. Один pending consent на цель; нельзя менять assignment/title начатого шага или принимать за другого. Бонус только в goal_reward_ledger (+50 Together XP) и space_progress, никогда в coin/reward ledger задач. Проверяйте freeze/leave/rejoin, view RLS, конкурентное завершение и COMMIT rollback на PostgreSQL; после изменения членства инвалидируйте couple-goals cache.

- Goal intents: храните UUID, исходный payload и expected counter вместе; retry никогда не перебазирует намерение. Проверка неизвестного результата — SELECT-only inspect_goal_request, а не повторная мутация. Новый UUID/повторная отправка требуют отдельного явного действия; не ставьте goal mutations в offline-очередь. Сверка Together XP read-only, исторические расхождения не исправлять автоматически.

- Достижения/статистика: `docs/achievements-statistics.md`. Нет новых наград; личные факты только auth.uid(), общий feed требует обоих исходных текущих участников. Together XP пространства отделять от истории нынешней пары. Сохраняйте UTC, opaque actor/epoch-bound live keyset cursor, keyset и server-side limit; не имитируйте строгий MVCC snapshot через xmin и не заменяйте их клиентской пагинацией. Первое acknowledge — молчаливая historical baseline, никакой клиентской записи codes/counters.

- Ритуалы: `docs/couple-rituals.md`. Отдельные факты без каких-либо XP/Coins/Together XP. Согласия фиксируют полный payload, экземпляры — version/terms snapshot; server UTC после user → space → ritual locks, только текущий подходящий день, без catch-up. Один pending consent блокирует новые отметки, unilateral withdraw должен оставаться доступным. Проверяйте weekly key/сутки/выход/повторное вступление, RLS обеих исходных сторон, cursor epoch, request fences и COMMIT rollback на PostgreSQL. Не переносите выполнение в task/reward ledgers и не удаляйте подтверждённую историю.

- Емоційна близькість: модуль `src/features/connection` українською; `docs/emotional-checkin.md`, `docs/couple-questionnaires.md`, `docs/between-us-card-game.md`. Не діагностуйте, не ранжуйте партнерів, не додавайте нагород чи зовнішніх AI API. JSON і SQL catalog seed перевіряйте `npm run check:connection-catalog`; опубліковані ID/тексти не змінювати заднім числом.
- `connection_*`: private drafts → explicit publication → both submitted. Поточні точні membership ID обох є межею доступу; вихід відкликає shared history також для повторного вступу тієї ж людини. Mood/answer aggregates не повинні розкривати приватних даних. Journal містить тільки hash intent, не тексти. Збережіть user → space → session locks, CAS поточної карти, server shuffle, no client deck index, own marks only. Зберігайте original intent між retry; перевірка невідомого результату SELECT-only. Не показуйте stale shared cache при помилці авторизації. Тестуйте дві сесії/UTC/COMMIT rollback на PostgreSQL та grants на справжньому локальному Supabase.

- Review PR #8: closed не відкриває чужих відповідей навіть старих карт; `unpublish` закриває всю сесію. Opt-out `heat`/`secret` доступний після completed і знімає власні старі `published` flags; opt-in не відновлює їх. Після epoch change receipt не розкриває старий session UUID. Перевіряйте обох читачів, RPC і прямий SELECT після кожної terminal-операції; не повертайте shared cached report для closed.

- Product Experience: `docs/product-experience.md`, `docs/ux-audit.md`. Сохраняйте пять вкладок, один основной следующий шаг и подтверждение опасных действий. Не превращайте onboarding/просмотр карты в согласие или публикацию. Проверяйте реальный screenshot front/back в Chromium и WebKit (`npm run test:browser`), включая reduced motion; CSS-матрицы сами по себе не доказывают отсутствие зеркалирования. Новые тексты карточек — новый выпуск и ID, старые `catalog.v1.json`, колоды и ответы неизменны; game_catalog_version фиксируется на создании игры.

- События пары: `docs/couple-activity-design.md`. Inbox — подтверждённые source triggers в той же транзакции, не optimistic UI. Не snapshot-ить приватные тексты; проверять текущий source-доступ и оба исходных membership ID также для metadata/reaction/прочтения. Сохраняйте bridge game acknowledged, уникальные envelope, CAS и original reaction UUID/expected/payload; проверка неизвестного результата SELECT-only, reconnect не отправляет мутации. Скрывайте shared cache при ошибке/epoch/offline. Новые источники требуют PostgreSQL rollback/leave/rejoin/consent/RLS тестов. Поддержка бесплатна, без XP/Coins, рейтингов и reaction-on-reaction. Live browser suite требует собственный disposable local Supabase и не допускает фиктивных сессий.

- Спогади: `docs/couple-memories-design.md`. Український album `/us/history`, stats `/us/progress`, 5 вкладок. Власний draft → explicit publication; кожен редагує лише власний текст/нотатки. Withdraw/delete не знищує чужі слова й не показує чужі metadata. Перевіряйте точні original membership ID, динамічний source access, receipt/CAS та server keyset. Фото тільки private `couple-memories` через Auth-checked `memory-files`, жодних raw client Storage policies/signed URLs. Не видаляйте possibly committed upload після timeout. Зберігайте staged/attached distinction і lock фото до validation проти GC. Service cleanup видаляє фізичний object перед prune, потребує окремого operator job. Не змінюйте економіку/старі міграції. Реальні Storage й Chromium/WebKit tests використовують тільки власні disposable local accounts; жодних remote SQL/Storage/deploy без окремого дозволу.
